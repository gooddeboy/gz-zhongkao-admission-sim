# 使用与部署说明

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11、macOS、Linux |
| Python | 3.10 及以上（推荐 3.13） |
| 数据库 | SQLite 3（Python 内置，无需安装） |
| 浏览器 | Chrome、Edge、Firefox 等现代浏览器 |
| 网络 | 本地运行不需要联网；首次安装依赖需要网络 |

## 2. 安装

```bat
cd zhongkao-admission
python -m pip install -r requirements.txt
```

依赖说明：

- `fastapi`、`uvicorn`：Web 框架与服务器；
- `pydantic`：请求模型；
- `pytest`、`httpx`：自动化测试。

文档生成依赖（可选）：

```bat
python -m pip install -r requirements-docs.txt
```

## 3. 初始化与启动

```bat
python run.py
```

或：

```bat
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000>；API 文档 <http://127.0.0.1:8000/docs>。

首次启动会自动创建：

- `data/admission.db`：SQLite 数据库；
- `data/snapshots/`：运行快照目录。

不需要手动执行建表脚本；如需重置，删除 `data/admission.db` 后重启即可。

## 4. 演示流程

### 4.1 小数据集（推荐用于验收）

1. 打开首页，点击“生成演示数据”。
2. 选择“人工小数据集（2 初中 / 4 高中 / 17 考生）”，确认重置。
3. 点击“新建投档运行”，参数：
   - G₁ = 720
   - Δ = 40
   - L = 600
   - 追踪级别：完整
4. 点击“完整运行”，等待四批完成。
5. 在“投档执行”页面查看：
   - 四个批次录取人数：3 / 5 / 6 / 2；
   - 第一批、第二批结转各 1 人；
   - 第三批 G02 有效计划 4 人；
   - 第四批 G04 余额 2 人。
6. 在“结果查询”输入 `C07`，查看：
   - 第二批被 G01-M01 校内竞争淘汰；
   - 第三批第一志愿 G01 已满，第二志愿 G02 录取；
   - 逐志愿原因和当时余额。
7. 输入 `C15`，查看“总分低于全市控制线”的未录取原因。
8. 在“统计分析”查看：
   - 最低录取分与末位考生分别计算；
   - G02 第三批最低 640，末位考生 C12/660/第 2 志愿；
   - 计划完成率 16/18 = 88.9%。
9. 打开“滑档案例”，运行“案例一”，查看 C1 从第四批录取变为第三批录取，以及 C2/C5 的挤出效应。

### 4.2 2 万人演示

1. 生成演示数据，选择“较大规模演示（300 初中 / 60 高中 / 2 万考生）”。
2. 新建运行，参数 G₁=712、Δ=40、L=492，追踪级别选“摘要”。
3. 完整运行约 3 秒。
4. 查看统计分析、结果查询、导出 CSV。

### 4.3 15 万人加分规模

1. 生成演示数据，选择“任务书加分规模（500 初中 / 150 高中 / 15 万考生）”。
2. 新建运行时追踪级别务必选择“摘要”，避免完整逐志愿日志占用过多空间。
3. 生成和运行需要更长时间；建议在演示前提前生成。

也可以命令行生成：

```bat
python scripts/generate_data.py --preset full --seed 2026
```

## 5. 操作说明

### 5.1 数据管理

- 高中、初中、考生、计划、资格、志愿均支持新增、编辑、删除；
- 支持 CSV 导入，导入采用“全有或全无”，任一行失败整体回滚；
- “运行校验”显示 error/warning；error 会阻止创建运行；
- 数据被运行锁定后，所有写操作返回 409；需点击“创建新数据版本”解锁。

CSV 表头：

| 类型 | 表头 |
| --- | --- |
| 高中 | `code,name,category,intake_batch,has_autonomous,total_plan,campus` |
| 初中 | `code,name,district` |
| 考生 | `candidate_no,name,middle_school_code,score,tie_seq` |
| 计划 | `high_school_code,batch,category,initial_quota,control_line,middle_school_code,note` |
| 资格 | `candidate_no,high_school_code,status,rank` |
| 志愿 | `candidate_no,batch,seq,high_school_code` |

### 5.2 投档执行

- “新建运行”会锁定数据并写入快照；
- “执行下一批”按 1→2→3→4 顺序执行；
- “完整运行”连续执行剩余批次；
- “一致性校验”检查唯一录取、计划不超额、名额平衡、有效志愿等；
- “下载输入快照”下载 gzip JSON；
- 已完成的运行不能重复执行；新建运行会生成独立结果。

### 5.3 结果查询

- 按考生编号精确查询，或按姓名片段搜索；
- 按高中/计划查看计划余额、最低录取分、末位考生和录取名单；
- 录取名单支持批次、高中筛选和 CSV 导出。

### 5.4 统计分析

- 计划完成率按“初始 + 转入 − 转出”计算，避免校内结转重复计数；
- 最低录取分与末位考生分别计算；
- 分数分布按 20 分一段；
- 支持导出计划、高中、初中、考生、录取名单、分数分布、未录取原因 CSV。

## 6. 数据备份与重置

备份：

```bat
copy data\admission.db data\admission_backup.db
xcopy data\snapshots data\snapshots_backup /E /I
```

重置：

1. 停止服务；
2. 删除 `data/admission.db`（以及 `data/admission.db-wal`、`data/admission.db-shm`）；
3. 重启服务，系统自动重建空库。

注意：删除数据库会丢失所有运行与快照索引；如需保留历史结果，请先备份。

## 7. 端口与访问

默认只监听 `127.0.0.1:8000`，仅本机访问。如需局域网访问：

```bat
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

并在防火墙放行 8000 端口。课程演示建议只在本机运行。

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| 端口 8000 被占用 | 改用 `--port 8001`，或结束占用进程 |
| 页面打开空白 | 检查是否通过 `python run.py` 启动；访问 `http://127.0.0.1:8000` 而不是直接打开 `index.html` |
| 修改数据提示 409 | 数据被运行锁定；点击“创建新数据版本” |
| 创建运行提示数据校验失败 | 打开“运行校验”，修复 error 项；warning 可保留 |
| CSV 导入失败 | 检查表头、编码（UTF-8）、编号是否存在、是否重复 |
| 运行很慢 | 15 万人数据使用“摘要”追踪；关闭其他占用 CPU 的程序 |
| 快照文件很大 | 15 万人完整追踪会记录大量逐志愿日志，改用摘要模式 |
| 想重新演示 | 生成数据时确认重置，或删除数据库后重启 |

## 9. 已知限制

- 单机单用户，无登录、权限和并发控制；
- SQLite 适合课程演示，不适合高并发生产环境；
- 大规模数据的完整追踪会显著增加数据库体积；
- 不模拟现实中的退档、补录、报到注册等流程；
- 历史运行与当前数据通过快照关联，跨数据版本查询需先选择对应运行。
