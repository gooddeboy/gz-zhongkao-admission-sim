# 核心算法

## 1. 梯度计算

```text
if score < L: 无梯度（不参与录取）
elif score >= G1: band = 1
else: band = 2 + floor((G1 - score - 1) / Δ)
```

性质：

- 分数恰好等于梯度线时归入较高梯度：720→1，719→2，680→2，679→3，640→3，639→4，600→4；
- 低于 L 返回 `None`，不进入任何批次的候选池；
- 最低梯度编号为 `2 + floor((G1 - L - 1) / Δ)`。

示例：G1=712，Δ=40，L=492：

| 梯度 | 区间 |
| --- | --- |
| 1 | ≥712 |
| 2 | 672–711 |
| 3 | 632–671 |
| 4 | 592–631 |
| 5 | 552–591 |
| 6 | 512–551 |
| 7 | 492–511 |

## 2. 总体顺序

```text
for batch in 1..4:
    if batch == 1: run_autonomous()
    if batch == 2: run_quota_allocation()
    if batch in (3,4): run_unified(batch)
    if batch == 1: transfer_batch1()
    if batch == 2: transfer_batch2()
    record_batch_outcomes()
```

每个批次内部：

```text
for band in 1..max_band:          # 高梯度优先
    if 本批所有计划已满: break
    for seq in 1..volunteer_limit: # 同梯度内志愿轮次
        groups = 按计划分组(本梯度、本志愿、未录取、满足控制线)
        for plan in groups:
            按 (-score, tie_seq, candidate_no) 排序
            录取前 remaining 名，其余标记为 OUTRANKED
```

## 3. 第一批 自主招生

```text
for plan in 第一批计划:
    eligible = []
    for volunteer in 报考该高中的第一批志愿:
        c = 考生
        if c 已录取: continue
        if c 低于 L: mark BELOW_CITY; continue
        q = 资格(c, 高中)
        if q 不存在: mark NO_QUALIFICATION; continue
        if q.status != qualified: mark DISQUALIFIED; continue
        if q.rank 为空: mark NO_RANK; continue
        if c.score < plan.control_line: mark BELOW_CONTROL; continue
        eligible.append((q.rank, c, volunteer))
    按 (rank, candidate_no) 升序
    录取前 remaining 名
```

- 考核排名是第一批的主要排序依据，不按总分排序；
- 排名唯一由数据校验保证；
- 计划控制线不得低于 L。

## 4. 第二批 名额分配

```text
for middle_school in 所有初中:
    band_map = 该校未录取考生按梯度分组
    for band in 1..max_band:
        if 该校所有第二批计划已满: break
        for seq in 1..3:
            groups = {}
            for c in band_map[band]:
                v = 考生第 seq 志愿
                if 无志愿: continue
                plan = 计划(高中=v.高中, 初中=该校)
                if 无计划: mark NO_ALLOCATION; continue
                if c.score < plan.control_line: mark BELOW_CONTROL; continue
                groups[plan].append((c, v))
            for plan in groups:
                按 (-score, tie_seq) 排序
                录取前 remaining 名
```

关键点：

- 每个初中独立处理，名额互不挤占；
- 同一初中内仍遵循“梯度优先 → 志愿轮次 → 分数/同分序号”；
- 无对应名额的志愿标记为 `NO_ALLOCATION`，不影响该考生其他志愿；
- 计划余额只在本初中计划内竞争。

## 5. 第三、第四批 统招

```text
band_map = 所有未录取、达到 L 的考生按梯度分组
for band in 1..max_band:
    if 本批所有计划已满: break
    for seq in 1..6:
        groups = {}
        for c in band_map[band]:
            v = 考生第 seq 志愿
            if 无志愿: continue
            plan = 计划(高中=v.高中, 批次)
            if 无计划: mark INVALID_PLAN; continue
            if c.score < plan.control_line: mark BELOW_CONTROL; continue
            groups[plan].append((c, v))
        for plan in groups:
            按 (-score, tie_seq) 排序
            录取前 remaining 名
```

关键点：

- 同一梯度内，第一志愿全部处理完后才处理第二志愿；
- 高梯度考生的后置志愿优先于低梯度考生的前置志愿；
- 计划满额后不再强行录取；
- 第三、第四批余缺不互转。

## 6. 名额结转

### 6.1 第一批结转

```text
for plan in 第一批计划:
    amount = plan.remaining
    if amount <= 0: continue
    target = 第三批计划(同一高中)
    plan.transferred_out += amount
    target.transferred_in += amount
    log_transfer(from_batch=1, from_plan=plan, amount, to_plan=target)
```

### 6.2 第二批结转

```text
for high_school in 有第二批计划的高中:
    total = sum(plan.remaining for plan in 该校第二批计划)
    if total <= 0: continue
    target = 第三批计划(该校)
    for plan in 该校第二批计划:
        amount = plan.remaining
        plan.transferred_out += amount
        log_transfer(from_batch=2, from_plan=plan, from_middle=plan.middle, amount, to_plan=target)
    target.transferred_in += total
```

- 先按高中汇总，再转入第三批；
- 每条来源计划保留流水；
- 每次运行从初始状态重建，重复运行不会叠加；
- 第三、第四批不生成结转。

## 7. 同分与排序

同一计划、同一轮次内的排序键：

```text
(-score, tie_seq, candidate_no)
```

- 总分降序；
- 同分时同分序号升序；
- 数据校验保证同一总分内同分序号唯一；`candidate_no` 只作为兜底确定性排序，不应在实际数据中触发。

## 8. 复杂度

设考生数 N、志愿数 V、计划数 P、梯度数 B、志愿轮次上限 S。

- 梯度计算：O(N)；
- 统招批次：每个梯度每个志愿轮次扫描该梯度考生并分组排序，最坏 O(B·S·N log N)，实际因计划满额提前停止；
- 名额分配：按初中分组后同量级，最坏 O(N log N) 左右；
- 第一批：按高中排序，O(Q log Q)，Q 为资格人数；
- 空间：O(N + V + P)。

2 万考生演示数据（60 高中、300 初中、约 11.8 万志愿）完整四批投档约 3 秒；15 万考生建议使用摘要追踪模式。

## 9. 为什么不能“按总分从高到低为每人搜索全部志愿”

如果先按总分从高到低逐人扫描所有志愿，会得到“分数绝对优先”的结果，破坏任务书要求的：

- **梯度优先**：高梯度考生的后置志愿应先于低梯度考生的前置志愿；
- **同梯度志愿优先**：同梯度内第一志愿应先于第二志愿，即使第一志愿考生分数更低。

本系统按“批次 → 梯度 → 志愿轮次 → 计划内排序”执行，先确定轮次，再在同一轮次内按分数排序，符合任务书规则。

## 10. 边界与异常

| 情况 | 处理 |
| --- | --- |
| 分数恰好等于梯度线 | 归入较高梯度 |
| 分数低于 L | 不参与录取，记录原因 |
| 计划控制线高于 L | 未达线者不投档 |
| 计划余额为 0 | 该轮次全部标记 OUTRANKED/PLAN_FULL |
| 本批计划全部满额 | 后续梯度不再扫描，标记 BATCH_FULL |
| 无人填报 | 计划保留余额，不强行录取 |
| 前批已录取 | 退出后续批次，标记 SKIPPED/ALREADY_ADMITTED |
| 第二批无对应名额 | 标记 NO_ALLOCATION，不影响其他志愿 |
| 结转后重复运行 | 新运行从初始状态重建，不叠加 |
| 运行中数据被修改 | 数据锁定 + 版本/哈希校验，拒绝继续执行 |

## 11. 一致性校验

每次批次执行后调用 `verify_run`：

1. 每名考生最多一条录取记录；
2. 每条计划录取数等于明细数；
3. 录取数不超过 `有效名额 − 转出`；
4. `初始 + 转入 − 转出 = 录取 + 余额`；
5. 录取记录对应有效志愿、批次、高中；
6. 第二批录取必须使用考生所属初中的计划；
7. 第一批录取必须有合格资格；
8. 计划内录取顺序连续（1..n）。

任何一项失败都会阻止结果落库，并把运行标记为失败。
