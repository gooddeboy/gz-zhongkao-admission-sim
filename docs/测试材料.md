# 测试材料：小数据集、人工预期与对照结果

> 本文件是课程设计“测试与验证”的核心材料。所有人工预期均在运行系统之前根据任务书规则推演得到；系统输出只用于与人工预期对照，不反向充当人工预期。

## 1. 测试环境与命令

- 运行环境：Windows 10/11，Python 3.13，SQLite 3（Python 内置）。
- 测试框架：pytest + FastAPI TestClient。
- 一键执行：

```bat
cd zhongkao-admission
python -m pytest -q
```

最近一次执行结果：`45 passed`。

测试文件对应关系：

| 文件 | 覆盖内容 |
| --- | --- |
| `tests/test_gradient.py` | 梯度边界、梯度优先、同梯度志愿优先、同分序号、边界分数 |
| `tests/test_batches.py` | 自主招生、跨批次排除、名额隔离、名额结转、不足额、系统约束、第三/四批不互转 |
| `tests/test_small_expected.py` | 小数据集完整人工预期对照、按批执行与完整运行一致性 |

| `tests/test_api.py` | API、按批执行、重复运行、数据锁定、导出、快照、异常导入、统计口径 |

## 4. 小数据集逐轮人工推演

### 4.1 第一批（自主招生）

第一批只看填报该校、在资格名单内、状态合格、总分 ≥ 计划控制线（600）的考生，按考核排名从小到大录取。

**G01（计划 1 人）**

- 有效候选：C01（排名 1）、C04（排名 2）；C03 无资格；C15 排名 4 但总分 599 < 600。
- 录取：C01（排名 1）。
- C04 因余额已满落选；C03 无资格；C15 低于全市控制线。
- G01 余额 = 1 − 1 = 0，无结转。

**G02（计划 3 人）**

- 有效候选：C02（排名 1）、C09（排名 2）；C11 资格不合格；C17 有资格但未填第一批志愿。
- 录取：C02（排名 1）、C09（排名 2）。
- G02 余额 = 3 − 2 = 1，全部转入 G02 第三批统招计划（计划 8）。
- 结转流水：第一批，来源计划 5，去向计划 8，人数 1。

### 4.2 第二批（名额分配）

第二批按“初中 → 梯度 → 志愿序号 → 同计划分数/同分序号”处理。不同初中名额互不挤占。

**M01（越秀一中）**

- 可竞争计划：G01-M01（2 人）、G02-M01（2 人）。
- 第 2 梯度（680–719）第一志愿：
  - G01-M01：C04（719）、C06（680）→ 按分数降序录取 C04、C06，计划满。
  - G02-M01：C05（700）→ 录取，余额 1。
- 第 2 梯度第二志愿：C04、C05 已录取，无新增。
- 第 3 梯度第一志愿：C07（679）报 G01、C08（640）报 G01，但 G01-M01 已满，均落选。
- M01 结果：C04、C06 被 G01 录取；C05 被 G02 录取；G02-M01 余额 1。

**M02（天河二中）**

- 可竞争计划：G01-M02（1 人）、G02-M02（1 人）。
- 第 1 梯度第一志愿：C16（720）报 G01 → 录取，G01-M02 满。
- 第 2 梯度第一志愿：C10（710）、C11（690）报 G01，但 G01-M02 已满，均落选。
- 第 2 梯度第二志愿：C10（710）报 G02 → 录取，G02-M02 满。
- 第 3 梯度：C12（660）第一志愿 G02 已满，第二志愿 G01 已满，落选。
- 第 4 梯度：C13（639）报 G01 已满；C14（600）报 G02 已满，均落选。
- C15 低于 L，不参与。
- M02 结果：C16 被 G01 录取；C10 被 G02 录取。

**第二批结束结转**

- G01 两个初中计划均满，余额 0。
- G02-M01 余额 1，G02-M02 余额 0；按高中汇总 G02 剩余 1 人，转入 G02 第三批计划 8。
- 结转流水：第二批，来源计划 6（G02-M01），去向计划 8，人数 1。

**结转后第三批有效名额**

- G01：初始 1，转入 0 → 1。
- G02：初始 2，第一批转入 1 + 第二批转入 1 → 4。
- G03：初始 1，转入 0 → 1。
- G04：初始 4，不受第一、二批影响 → 4。

## 6. 高分滑档案例人工推演

### 6.1 案例一：某批次未录取（第三批滑档，第四批被录取）

参数：G₁=720，Δ=40，L=600。H1、H2 为第三批各 1 人；H3 为第四批 2 人。

基线志愿：

- C1（700，第 2 梯度）：第三批 1=H2，2=H1；第四批 1=H3。
- C2（690，第 2 梯度）：第三批 1=H1。
- C3（715，第 2 梯度）：第三批 1=H2。
- C4（650）：第四批 1=H3。
- C5（640）：第四批 1=H3。
- C6（730）：未填志愿。

第三批推演：

1. 第 2 梯度第一志愿：H1 的 C2（690）录取，H1 满；H2 的 C3（715）录取，H2 满。
2. 第 2 梯度第二志愿：C1（700）报 H1，但 H1 已被 C2 占满，落选。
3. C1 的第一志愿 H2 也在第一志愿轮次被 C3（715 > 700）占满，因此 C1 第三批两个志愿均落空。
4. C1 第三批未录取，进入第四批。

第四批推演：

1. 第 2 梯度第一志愿：C1（700）报 H3 → 录取（顺序 1）。
2. 第 3 梯度第一志愿：C4（650）、C5（640）报 H3 → C4 录取（顺序 2），C5 落选。

基线结果：C1 第四批 H3；C2 第三批 H1；C3 第三批 H2；C4 第四批 H3；C5、C6 未录取。

调整后：只把 C1 的第三批志愿改为 1=H1、2=H2。

1. 第 2 梯度第一志愿：H1 的 C1（700）与 C2（690）竞争，C1 录取，C2 落选；H2 的 C3（715）录取。
2. C1 已在第三批 H1 录取，退出后续批次。
3. 第四批：C4（650）、C5（640）报 H3，H3 有 2 个名额，C4、C5 均录取。

调整后结果：C1 第三批 H1；C2 未录取；C3 第三批 H2；C4、C5 第四批 H3。

对照结论：

- C1 从“第三批未录取、第四批才录取”变为“第三批第一志愿录取”，志愿顺序调整避免了该批次滑档。
- 同时出现挤出效应：C2 因 C1 前移而落选；C5 因 C1 不再占用第四批名额而获得录取。
- 该案例满足“同一梯度内低分考生因志愿靠前被录取、高分考生因该校志愿靠后落选，且未被该批次其他志愿录取”。

### 6.2 案例二：全部批次结束后仍未录取

参数同上。H1、H2 第三批各 1 人；H3 第四批 1 人。

基线志愿：

- C1（710，第 2 梯度）：第三批 1=H2，2=H1；无第四批志愿。
- C2（690，第 2 梯度）：第三批 1=H1。
- C3（720，第 1 梯度）：第三批 1=H2。
- C4（680，第 2 梯度）：第四批 1=H3。
- C5（650，第 3 梯度）：第四批 1=H3。

推演：

1. 第 1 梯度第一志愿：C3（720）报 H2 → 录取，H2 满。
2. 第 2 梯度第一志愿：C2（690）报 H1 → 录取，H1 满；C1（710）报 H2，但 H2 已满，落选。
3. 第 2 梯度第二志愿：C1（710）报 H1，但 H1 已被 C2 占满，落选。
4. 第四批：C4（680）与 C5（650）报 H3，C4 录取，C5 落选；C1 无第四批志愿。
5. 全部批次结束，C1 未录取。

调整后：只给 C1 增加第四批 1=H3。

1. 第三批结果不变，C1 仍未被第三批录取。
2. 第四批第 2 梯度第一志愿：C1（710）与 C4（680）竞争 H3 的 1 个名额，C1 录取，C4 落选。
3. C1 避免全批次滑档；C4 被挤出。

对照结论：高分考生只填热门高中且不填保底志愿，会在所有批次结束后仍未录取；增加保底志愿即可避免。

## 7. 大规模数据测试

生成预设：

| 预设 | 初中 | 高中 | 考生 | 用途 |
| --- | --- | --- | --- | --- |
| small | 2 | 4 | 17 | 人工推演与边界测试 |
| medium | 100 | 30 | 3,000 | 开发调试 |
| demo | 300 | 60 | 20,000 | 课堂演示 |
| full | 500 | 150 | 150,000 | 任务书加分规模 |

生成命令（也可在 Web 界面“生成演示数据”中操作）：

```bat
python scripts/generate_data.py --preset demo --seed 2026
```

实际测试记录（本机）：

- demo（2 万考生）：生成、完整四批投档、统计查询均在数秒内完成；所有计划满足名额平衡等式。
- full（15 万考生）：作为加分规模提供，建议使用摘要追踪模式（`trace_level=summary`）以控制日志与数据库体积；完整追踪会记录逐志愿原因，数据量较大。

大规模数据验证点：

1. 每名考生最多一条录取记录；
2. 每条计划录取数不超过有效名额；
3. 初始 + 转入 − 转出 = 录取 + 余额；
4. 汇总统计与明细一致；
5. 相同随机种子生成结果一致。
