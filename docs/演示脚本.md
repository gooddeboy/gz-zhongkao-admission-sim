# 演示脚本（5–8 分钟）

## 0. 演示前准备

1. 启动系统：`python run.py`，浏览器打开 <http://127.0.0.1:8000>。
2. 建议提前生成小数据集并完成一次运行，避免现场等待。
3. 准备两个浏览器标签页：
   - 标签 1：系统首页；
   - 标签 2：`/docs` API 文档（备用）。
4. 确认“投档执行”中有一个已完成的小数据集运行；若无，按下面步骤现场生成。

## 1. 开场（30 秒）

> “本系统按任务书简化规则模拟广州中考公办高中录取：四个批次、梯度优先、志愿轮次、名额分配隔离、剩余名额结转，并保存输入快照与完整投档日志。”

展示首页 KPI：高中、初中、考生、计划、最近运行。

## 2. 数据与规则（1 分钟）

1. 点击“数据管理” → “招生计划”。
2. 说明三类计划：
   - 第一批自主招生；
   - 第二批名额分配（按高中+初中）；
   - 第三批/第四批统招。
3. 点击“自主招生资格”和“志愿”，说明资格排名、志愿上限（1/3/6/6）。
4. 点击“运行校验”，展示 error/warning 分类。

## 3. 完整投档（1.5 分钟）

1. 点击“投档执行” → 打开已完成的运行（或新建）。
2. 展示四个批次步骤条：录取 3 / 5 / 6 / 2。
3. 展示计划余额卡片：
   - 第一批、第二批各结转 1 人到第三批；
   - 第三批 G02 有效计划 4 人；
   - 第四批 G04 余额 2 人。
4. 点击“结转流水”，展示来源计划、去向计划、人数。
5. 点击“一致性校验”，展示“通过”。

## 4. 结果解释（1.5 分钟）

1. 点击“结果查询”，输入 `C07`。
2. 说明：
   - 第二批：G01-M01 校内竞争，C07 679 分排在同计划更高分考生之后，落选；
   - 第三批第一志愿 G01 已满，第二志愿 G02 录取；
   - 每个志愿的“当时余额”可追溯。
3. 输入 `C15`：
   - 599 分低于 L=600，四个批次均不具资格；
   - 说明“低于控制线”不是“计划已满”。

## 5. 统计口径（1 分钟）

1. 点击“统计分析”。
2. 指出：
   - 计划完成率 16/18 = 88.9%（初始 18，转入 2，转出 2）；
   - G02 第三批最低录取分 640；
   - 末位考生 C12，660 分，第 2 志愿，同分序号 1；
   - “最低分”和“末位考生”不是同一个概念。
3. 点击导出 CSV，展示可交付结果。

## 6. 滑档案例对照（1.5 分钟）

1. 点击“滑档案例”，运行“案例一”。
2. 说明基线：
   - C1 700 分，第三批第一志愿 H2、第二志愿 H1；
   - 同梯度 C2 690 分第一志愿 H1，先占满 H1；
   - C1 第一志愿 H2 被 715 分 C3 占满，第三批落选；
   - C1 第四批才被 H3 录取。
3. 说明调整后：
   - 只把 C1 第三批志愿改为 H1 在前；
   - C1 第三批被 H1 录取；
   - C2 被挤出，C5 因 C1 不再占第四批名额而录取。
4. 运行“案例二”：
   - C1 710 分只填两所热门高中、不填保底，全部批次结束仍未录取；
   - 增加第四批 H3 志愿后被录取。
5. 结论：志愿顺序和保底志愿会影响滑档；系统能复现并解释挤出效应。

## 7. 边界场景（可选，30 秒）

### 场景 A：同梯度志愿优先

- A 校 2 人；甲 690 分第 1 志愿，乙 710 分第 2 志愿；B 校被 720 分考生占满。
- 结果：甲先录取，乙后录取；A 校最低分 690，末位考生乙 710/第 2 志愿。

### 场景 B：名额分配隔离

- M1 有 700/690 分，M2 有 710/600 分；M1/M2 各 1 个名额。
- 结果：M1 700 分录取，690 分不能挤占 M2 名额；M2 710 分录取。

## 8. 检查问题准备

| 问题 | 回答要点 |
| --- | --- |
| 为什么不能简单按总分从高到低为每人搜索全部志愿？ | 会变成“分数绝对优先”，破坏同梯度志愿优先和梯度优先；必须先批次、再梯度、再志愿轮次，最后才在同一计划同一轮次按分数排序。 |
| 为什么名额分配要保留所属初中？ | 名额是高中分给具体初中的，考生只能竞争自己初中的名额；否则弱校名额会被强校考生挤占。 |
| 末位考生一定是录取最低分考生吗？ | 不一定。末位考生按计划实际录取顺序最后一人；最低分是分数最小值。低分第一志愿可能先录取，高分第二志愿后录取，因此末位分数可能更高。 |
| 同一批次是否保证“同梯度志愿优先、不同梯度梯度优先”？ | 是。代码按 band 外层、seq 内层处理；测试覆盖 730 分第 2 志愿先于 700 分第 1 志愿，以及 690 分第 1 志愿先于 710 分第 2 志愿。 |
| 是否存在名额分配最低分高于统招最低分的倒挂？ | 可能。名额分配是校内竞争，强校初中名额少、考生分数高，可能出现名额分配最低分高于统招最低分；本系统可按初中/计划查询并比较。 |

## 10. 演示失败预案

- 若现场运行慢：提前生成并完成一次运行，直接打开已有结果。
- 若端口被占用：改用 `python -m uvicorn app.main:app --port 8001`。
- 若数据被锁定：点击“创建新数据版本”后再修改；或直接使用已有运行结果演示。
- 若浏览器异常：使用 `/docs` 调用 API 展示同一结果。
- 若投影分辨率低：浏览器缩放到 90%，或只展示关键表格。
