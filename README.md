# 简化广州中考公办高中录取模拟系统

课程设计项目：面向广州中考招生机制，按任务书简化规则实现四批次投档、名额分配、梯度志愿、计划结转、结果查询与统计分析的完整可运行系统。

- 技术栈：Python 3.13 + FastAPI + SQLite + 原生 HTML/CSS/JavaScript
- 运行方式：本地启动，无需 Node、无需外部数据库、无需联网
- 测试：`pytest` 45 项自动化测试全部通过
- 规模：内置 17 人小数据集、3 千人、2 万人演示数据和 15 万人加分规模生成器

## 1. 功能概览

| 模块 | 功能 |
| --- | --- |
| 数据管理 | 高中、初中、考生、招生计划、自主招生资格、志愿的增删改查、CSV 导入与校验 |
| 投档执行 | 按批执行 / 完整运行、输入快照、计划余额、结转流水、事件日志、一致性校验 |
| 结果查询 | 按考生、高中/计划、批次查询录取去向、志愿处理过程与未录取原因 |
| 统计分析 | 计划完成率、录取人数、分数分布、各计划最低录取分与末位考生、CSV 导出 |
| 滑档案例 | 两个高分滑档案例的基线与志愿调整对照，展示挤出效应 |
| 版本管理 | 运行锁定数据版本、gzip 快照 + SHA-256、重复运行结果独立 |

## 2. 快速开始

环境要求：Python 3.10+（推荐 3.13），Windows / macOS / Linux。

```bat
cd zhongkao-admission
python -m pip install -r requirements.txt
python run.py
```

Windows 用户也可以直接双击项目根目录的 **`启动系统.bat`**：保持弹出的命令行窗口打开，然后在浏览器访问 <http://127.0.0.1:8000>。关闭窗口即停止服务。

浏览器打开 <http://127.0.0.1:8000>。

首次使用建议：

1. 点击“生成演示数据”，选择“人工小数据集（2 初中 / 4 高中 / 17 考生）”。
2. 点击“新建投档运行”，参数保持 G₁=720、Δ=40、L=600，追踪级别选“完整”。
3. 点击“完整运行”，等待四批执行完成。
4. 在“结果查询”输入 `C07` 查看逐志愿处理原因；在“统计分析”查看计划余额与末位考生。
5. 打开“滑档案例”，运行“案例一”查看基线与志愿调整后的对照。

也可以直接使用 API 文档：<http://127.0.0.1:8000/docs>。

## 6. 关键设计

### 6.1 投档顺序

严格按批次 1 → 2 → 3 → 4 执行；每批先处理高梯度，再处理低梯度；同一梯度内先处理第一志愿，再处理第二志愿，依次类推；同一计划、同一轮次按总分降序、同分序号升序录取。

### 6.2 名额分配

第二批按（高中, 初中）分计划，考生只能竞争所属初中获得的名额，不同初中名额互不挤占。第二批结束后先按高中汇总各初中剩余名额，再转入第三批统招计划。

### 6.3 计划结转

- 第一批剩余 → 本校第三批统招；
- 第二批按高中汇总剩余 → 本校第三批统招；
- 第三、第四批余缺不互转；
- 每次运行从初始状态重新计算，结转只发生一次，不叠加。

### 6.4 版本与快照

每次运行保存 gzip JSON 快照和输入哈希；运行完成后锁定当前数据版本。修改输入需“创建新数据版本”，历史运行结果与快照保持不变。重新运行创建独立运行编号，不叠加旧录取。

### 6.5 统计口径

- 最低录取分 = 该计划已录取考生总分最小值；
- 末位考生 = 按计划实际录取顺序最后录取的人，另报总分、志愿序号、同分序号；
- 二者分别计算，末位考生分数可能高于最低录取分；
- 无人录取显示“无”，不用 0 分代替；
- 学校总体、分批、分类计划统计分开。

## 8. 已知限制

- 本系统是教学模拟，不完整复现现实政策；户籍、区域、随迁子女、参考科目、特长生等均已简化。
- 不模拟退档、放弃录取、报到注册和正式补录。
- 大规模数据（15 万人）建议使用“摘要”追踪级别，以控制数据库体积和查询时间。
- 前端为原生 JavaScript 单页应用，未做多用户并发与权限控制。
- 历史运行结果与当前数据版本通过快照关联；如需保留多个数据版本，请自行备份 `data/admission.db`。
